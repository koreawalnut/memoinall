# 사용성 검토 및 개선

검토 기준: 형식 없이 기록하고, 필요한 기록을 검색해 AI 결과물로 만들며, 일부만 동료에게 전달하고 외부 메모를 가져오는 흐름.
화면, API, 저장·검색·AI 생성·파일 교환·가져오기 구현과 기존 테스트를 함께 확인했다.

## 주요 판단

입력할 때 분류를 강요하지 않는 방향은 유지했다. 개선의 중심은 작성 내용 보호, 검색 범위의 가시성, 사용할 메모의 직접 선택이다.
기존에는 기능별 메뉴가 있어도 사용자가 고른 범위가 다음 단계에 정확히 전달되지 않는 문제가 있었다.

|---|---|---|
| 높음 | 처음 사용하는 사람에게 상단 7개 기능과 검색·선택·공유 도구가 한꺼번에 보여 다음 행동을 고르기 어려움 | 주메뉴를 내 메모·AI로 정리·가져오기·공유의 세 가지로 축소. 보조 메뉴와 상세 설정은 접고, 메모 선택 후 활용 도구 표시 |

## 사용 흐름

1. **기록:** ‘내 메모’에서 입력하면 ‘초안 보관됨’이 표시된다. `Ctrl+Enter` 또는 ‘메모 저장’으로 검색 가능한 메모를 만든다. 데스크톱의 실행 포트가 바뀌어도 서버 DB에서 초안을 복원한다.
2. **찾기:** 검색창에 기억나는 단어나 내용을 적는다. 필요하면 ‘상세 검색’을 열어 작성일을 지정하고 태그·사람 조건을 조합한다. 접은 뒤에도 적용 중인 조건은 화면에 남고 개별 해제가 가능하다.
3. **일부 인수인계:** ‘메모 선택’을 누르고 필요한 메모를 체크한 뒤 ‘공유·인수인계’를 누른다. 나갈 목록을 확인하고 전달할 한 줄 설명을 적어 파일로 저장한다. 직접 선택한 경우 검색 조건 입력은 비활성화되며 선택한 메모만 전달된다.
4. **AI 활용:** 주메뉴 ‘AI로 정리’에서 목적과 형식을 지정하거나, 메모를 선택한 뒤 나타나는 ‘AI로 정리’를 누른다. 인수인계서는 업무 배경·현재 상태·결정 사항·남은 할 일·참고 자료를 정리한다. 담당자나 기한이 기록에 없으면 만들어내지 않도록 지시한다.
5. **가져오기·받기:** ‘가져오기·공유’에서 ‘다른 앱에서 가져오기’ 또는 ‘동료와 주고받기’를 고른다. 문서 파일은 텍스트를 미리 보고 수정·선택한 뒤 저장한다. 받은 .json 파일은 확인 후 가져오기를 실행한다. 문서 형식과 제한은 [문서 파일 가져오기](document-import.md)를 참고한다.

## 메뉴와 도구를 보여주는 기준

| 기본 화면 | 필요할 때 여는 기능 |
|---|---|
| 내 메모·AI로 정리·가져오기·공유의 세 주메뉴 | 더 보기에서 할 일·주제별·기간 요약·설정 |
| 새 메모 입력창과 메모 검색 | 상세 검색에서 작성일과 조건별 공유 |
| 읽을 수 있는 메모 목록과 ‘메모 선택’ 버튼 | 선택 모드에서 체크박스, 선택 후 AI 정리·공유·인수인계 |
| AI 요청과 결과 형식 | 자료 범위·상세 설정에서 검색 범위와 자료 분량 |
| 가져올 앱 또는 동료와 주고받을 파일 | Redmine 연결과 가져오기 옵션, 내보내기 검색 조건 |

등록한 태그가 없을 때는 태그 설정을 요구하는 안내를 입력창에 표시하지 않는다. 태그가 있으면 ‘태그 추가 (선택)’에서 펼쳐 넣는다.
다른 앱의 ‘전체 가져오기’는 해당 화면의 네 소스만 대상으로 하고, 동료에게 받은 파일은 별도 흐름으로 처리한다.

기존 메모는 상세 화면의 **태그**에서 새 태그 입력·사용한 태그 선택·태그 제거를 지원한다.
다른 메모와 공용 태그 이름에 영향을 주지 않으며 **저장**할 때 본문과 함께 반영한다.
본문의 `#태그`와 편집 표시가 함께 바뀌고, 저장 전 닫기 확인은 입력 중인 태그도 보호한다.
저장 직후 필터·검색·공유에서 새 태그를 사용하도록 원문·검색 색인·태그를 한 트랜잭션으로 갱신한다.

## 동작 범위

- 초안은 새 메모 하나를 보관한다. 기존 메모 편집은 닫기 전 변경 확인으로 보호한다. ‘초안 보관됨’ 전에 프로세스가 강제 종료되면 마지막 입력이 서버에 도착하지 않았을 수 있다.
- 직접 선택한 ID 목록이 비어 있으면 전체로 확대하지 않는다. AI 근거 선택의 ID가 잘못됐거나 삭제됐으면 오류로 알린다. API 선택은 요청당 최대 1000건이다.
- 선택한 메모 중 토큰 예산 때문에 빠지거나 일부만 포함된 내용은 근거 화면에 표시한다.
- 생성 중에는 입력을 잠가 화면의 지시사항과 진행 중인 요청이 달라지는 것을 막는다.
- 서버 초안은 기존 SQLite `meta`에 저장하므로 별도 데이터베이스 이전은 필요 없다.

## 검증

- 기존 및 추가한 Python 테스트 9개 파일: **658개 통과, 실패 0**. 데스크톱 포트 검사는 일시적 재바인딩 충돌 후 재실행으로 통과를 확인했다. 실행 중인 앱과 충돌하는 중복 실행 잠금 검사는 건너뛰었다. 빌드 환경 선택 테스트 5개도 통과했다.
- Playwright Chromium에서 주요 흐름 16개 통과: 기본 화면의 메뉴·도구 노출, 보조 메뉴의 키보드·마우스 접근, 페이지를 넘긴 선택·정확한 내보내기, 선택 AI 근거·인수인계 형식·출처 열기, 접은 검색 조건 유지·전달, 받은 파일 선택·미리보기·가져오기, 가져오기와 공유의 화면·일괄 범위 분리, 문서 업로드·편집 유지·부분 저장·AI 연결, 이미지 문서 OCR 안내, 미저장 편집 보호, 태그 제거·다른 태그 및 서식 보존·미저장 입력 보호, 태그 추가·검증·본문 동기화·저장·검색, 초안 복원, 중복 저장·저장 중 입력 보호, 지연 검색 응답 처리, 좁은 화면.
- 테스트는 임시 DB를 사용한다. 실제 LLM 호출은 가짜 출력으로 대체하며 서버가 선택한 근거 범위는 그대로 검증한다. API 키와 모델 다운로드가 필요 없는 회귀 경로를 사용했다.
- 삼성 노트 실제 데이터가 없어 실제 사용자 DB를 이용하는 가져오기 검사는 건너뛰었다. 임시 SQLite 자료를 이용한 임포터 검사는 통과했다.
- 실제 데스크톱 WebView2 창, 실제 LLM의 결과 품질, 실제 사용자 데이터에서의 검색 관련성은 검증 범위에 포함하지 않았다. 후속 빌드 오류 수정에서 Windows 실행 파일을 생성하고 문서 파서 포함을 확인했다.

브라우저 테스트는 선택 의존성 `playwright`와 Chromium이 설치된 환경에서 다음과 같이 실행한다.

```powershell
python -X utf8 tests/test_api.py
python -X utf8 tests/test_memoinall.py
python -X utf8 tests/test_ui.py
# 화면 캡처도 남기려면
python -X utf8 tests/test_ui.py --screenshots
```

## 실제 사용 자료로 확인할 다음 과제

다음 항목은 기능이 필요한 범위와 실제 자료를 확인한 뒤 설계하는 것이 적절하다.

- **외부 앱의 읽기 누락 안내:** Samsung Notes는 이미 인식된 텍스트를 읽는다. 이미지·필기에서 인식 텍스트가 없는 경우, 원본 건수·읽은 건수·누락 사유를 비교할 수 있는 보고 방식이 필요하다. 실제 삼성 노트 자료와 버전별 스키마를 확보해 검증해야 한다.
- **가져오기 항목별 선택:** 현재 외부 앱 가져오기는 소스와 최소 길이 등으로 좁힌다. 일부 기록만 가져오는 요구가 많은지 확인한 뒤 항목별 선택과 대용량 미리보기를 설계할 수 있다.
- **인수인계 후 진행 상태:** 지금은 선택한 기록을 파일로 전달하고 받는 흐름이다. 전달·수신·완료 상태나 담당자 변경까지 필요한지 확인하면 기록 교환을 업무 관리로 확장할 수 있다.
- **검색 관련성 평가:** 실제 메모와 자주 쓰는 질문으로 정답 자료를 만들고, 의미 검색 모델의 관련성과 낮은 관련성 결과의 처리 방식을 평가하는 것이 다음 단계다.
