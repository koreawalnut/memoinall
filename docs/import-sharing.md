# OneNote·에버노트 가져오기와 공유 대상 확인

## 출처 태그와 시간 표시

외부 앱에서 가져오면 `#OneNote`, `#에버노트`, `#스티커메모`, `#삼성노트`, `#Redmine`, `#텍스트파일` 중
해당 출처 태그가 자동으로 붙습니다. 원래 태그는 유지하고 같은 태그를 중복해서 붙이지 않습니다.
문서 파일은 기존처럼 `#문서`와 파일 형식 태그가 붙습니다. 동료가 보낸 메모 파일은 원래 태그를 유지합니다.
가져오기 직후부터 태그로 찾을 수 있습니다.

가져온 본문에서 `#1234`, `#1234번`, `#note-2` 같은 참조 번호는 본문 검색으로 찾을 수 있습니다. `#배포`, `#2차회의` 같은 주제어와 Redmine 프로젝트·트래커는 태그 필터에도 표시됩니다.
숫자를 분류에 쓰려면 가져오기의 추가 태그나 메모 상세의 **태그 추가**에서 직접 지정하세요. 원본 앱이 태그로 지정한 숫자도 보존합니다.
업데이트 후 앱을 열면 기존에 가져온 메모의 번호 태그도 한 번 정리합니다. 본문과 작성·수정 시각은 유지됩니다.

기존에 가져온 메모에도 앱 실행 후 백그라운드에서 한 번 출처 태그를 보완합니다.
이 작업으로 작성·수정 시각은 바뀌지 않으며, 이후 직접 지운 태그를 실행할 때마다 되붙이지 않습니다.
자동 태그를 붙이기 전에 공유했던 파일도 같은 내용이면 다시 저장하지 않습니다.

시간은 이 PC의 현지 시각을 `2026-11-09 14:30`처럼 24시간제로 표시합니다.
메모 상세 화면에서 작성 시각과 수정 시각을 구분합니다.
구버전에서 Redmine·스티커 메모의 시간대를 누락한 경우, 해당 앱에서 **가져오기**를 다시 실행하면
원본과 대조해 잘못된 시각만 바로잡습니다. **이미 가져온 메모도 갱신**을 켤 필요는 없습니다.
직접 수정한 본문과 수정 시각은 유지합니다. 원본을 확인할 수 없는 시각은 임의로 바꾸지 않습니다.

## OneNote에서 옮기기

### PC에서 전자 필기장 일괄 가져오기

1. 이 PC의 Windows용 OneNote 데스크톱 앱에서 가져올 전자 필기장을 엽니다. 로컬 `.one` 섹션도 앱에서 먼저 여세요.
2. **가져오기·공유 → 다른 앱에서 가져오기 → PC의 OneNote 전자 필기장**에서 **가져올 페이지 미리보기**를 누르면 신규·기존 페이지 수와 일부 제목을 확인할 수 있습니다.
3. **전자 필기장 일괄 가져오기**를 누르면 열려 있는 모든 전자 필기장의 텍스트 페이지가 각각 메모로 저장됩니다. 다른 앱과 함께 **전체 가져오기**를 실행해도 포함됩니다.

원본의 전자 필기장·섹션 이름과 작성·수정 시각을 함께 가져옵니다. 페이지 ID를 기준으로 중복을 건너뛰며, **이미 가져온 메모도 갱신**을 켜면 원본의 변경 내용을 다시 반영합니다.
잠긴 섹션은 OneNote에서 잠금을 풀고 다시 시도할 수 있습니다. 휴지통은 제외하고, 그림·필기·첨부파일은 원본에서 확인합니다. [Microsoft OneNote 데스크톱 API](https://learn.microsoft.com/office/client-developer/onenote/application-interface-onenote)

### PDF 또는 Word로 내보낸 파일에서 선택하기

1. Windows용 OneNote에서 페이지나 섹션을 열고 **파일 → 내보내기**로 PDF 또는 Word(.docx)를 저장합니다. 웹용 OneNote에서는 페이지를 열고 **파일 → 인쇄**에서 PDF로 저장합니다. [Windows용 내보내기 형식](https://support.microsoft.com/en-us/onenote/onenote-platform-data-protection-recovery) · [웹용 PDF 저장 방법](https://support.microsoft.com/en-us/onenote/onenote-for-web-help-and-learning/export-notes-as-a-pdf-in-onenote-for-the-web)
2. memoinall의 **가져오기·공유 → 다른 앱에서 가져오기 → OneNote 내보내기 파일 (PDF·Word)**에서 파일을 선택합니다. 파일당 20MB까지 읽습니다.
3. 미리보기에서 필요한 항목을 체크하고 **선택 N건 가져오기**를 누릅니다. PDF는 인쇄된 쪽으로 나누고 Word는 명시적인 쪽 나누기를 사용합니다. 쪽 나누기가 없는 Word 문서는 메모 한 건이 됩니다.

메모에는 텍스트, 원본 파일명과 위치, `#OneNote` 태그가 남습니다. 필기·이미지·첨부파일은 원본에서 확인하세요. 작성 시각은 가져온 시각으로 기록됩니다. 같은 파일명의 같은 쪽을 다시 가져오면 건너뛰고, 본문이 달라진 쪽은 새 메모로 가져옵니다.

## 에버노트에서 옮기기

1. Evernote Windows/Mac 앱에서 메모 또는 노트북을 선택하고 **내보내기 → ENEX**를 선택합니다. 태그·작성일·수정일도 내보내세요.
2. memoinall의 **가져오기·공유 → 다른 앱에서 가져오기 → 어디에 적어두셨나요?** 에서 Samsung Notes 아래
   **Evernote (에버노트)** 칸의 파일 선택으로 `.enex` 파일을 고릅니다.
3. 목록에서 제목·본문을 검색하고 **본문 확인**을 펼쳐 내용을 확인합니다. 필요 없는 메모는 체크를 해제합니다.
4. **선택 N건 가져오기**를 누릅니다. 미리보기만으로는 저장하지 않습니다.

제목, 텍스트, 링크, 체크리스트, 작성·수정 시각, 태그를 가져옵니다. 날짜는 이 PC의 현지 시각으로 변환합니다.
태그의 공백은 밑줄로 바꾸고, 앱의 태그 규칙에 맞지 않는 이름은 본문에 원문으로 보존합니다.
노트북별로 구분하려면 파일을 나눠 내보내고 가져오기 옵션에서 분류용 태그를 붙이세요.

이미지·첨부파일의 실제 데이터, 서식, 암호화된 본문은 옮기지 않습니다. 첨부 위치·이름과 암호화된 부분의 표시를
텍스트로 남기고 목록에 주의사항을 보여 줍니다. 원본 ENEX는 보관하세요. 암호화된 내용이 필요하면 Evernote에서
암호를 해제한 뒤 다시 내보내야 합니다. 이 기능은 ENEX 파일을 읽는 방식이며 계정 동기화 기능은 아닙니다.

같은 내용을 다시 가져오면 건너뜁니다. ENEX에는 안정적인 메모 ID가 보장되지 않아 **내용을 수정한 뒤 다시 내보낸
메모는 새 메모로 취급**합니다. 기존 메모를 자동으로 찾아 덮어쓰지는 않습니다.
UI 파일당 제한은 **50MB·1,000건**이며 넘으면 나눠 내보내야 합니다.

Evernote의 내보내기 절차는 [공식 도움말](https://help.evernote.com/hc/en-us/articles/209005557-Export-Notes-and-Notebooks-as-ENEX-or-HTML),
본문 구조는 [ENML 명세](https://dev.evernote.com/legacy/doc/articles/enml)를 참고했습니다.

CLI에서도 지원합니다. `--commit`을 생략하면 읽기만 합니다.

```powershell
python -m memoinall import --source evernote --evernote-file "C:\notes\archive.enex"
python -m memoinall import --source evernote --evernote-file "C:\notes\archive.enex" --commit
```

## 동료와 주고받기

### Teams로 보내기

- **메모 한 건을 채팅 본문으로** 보내려면 메모 상세에서 **Teams로 본문 공유**를 누릅니다. Windows 데스크톱 앱은 Teams 새 채팅을 직접 열고, 브라우저에서는 Teams 채팅 링크를 엽니다. 현재 편집한 본문이 초안에 들어가며 클립보드에도 복사됩니다. Teams에 이전 초안이 남아 있거나 긴 본문을 붙여넣으라는 안내가 나오면, 받는 사람을 고른 뒤 입력란에 붙여넣으세요. 메모 상세의 **본문 복사**로도 다시 복사할 수 있습니다.
- **메모 여러 건을 첨부파일로** 보내려면 **가져오기·공유 → 동료와 주고받기**에서 보낼 메모를 체크하고 **Teams로 파일 공유**를 누릅니다. Windows 앱이 선택한 메모와 비밀번호 설정을 반영한 `.json` 파일을 준비하고 **Windows 공유 창**을 엽니다. 목록에서 **Microsoft Teams**를 고르면 파일이 첨부되고 안내 글이 채워진 채로 Teams 공유 창이 열립니다. 받는 사람을 고르고 보내면 동료가 **받은 메모 파일 넣기**에서 가져올 수 있습니다. 암호화한 파일이면 비밀번호는 따로 알려주세요.
- **일정을 첨부파일로** 보내려면 **일정 → 일정 공유**에서 보낼 일정을 확인한 뒤 **Teams로 공유**를 누릅니다. 고른 일정만 담은 `.ics` 파일이 같은 방법으로 첨부되고, 날짜·요일·시간·제목·태그를 적은 일정 목록이 글로 함께 들어갑니다. 받는 사람은 파일을 열지 않아도 무엇이 왔는지 볼 수 있고, `.ics`를 열면 자기 캘린더에 추가할 수 있습니다.

Teams 새 채팅 링크로는 글만 미리 채울 수 있고 파일은 붙일 수 없어서 Windows 공유 창을 씁니다. 새 Teams(Microsoft Store 버전)가 공유 대상으로 나타납니다. 다음 경우에는 공유 창 대신 예전 방식(파일을 클립보드에 담고 Teams 새 채팅 열기 → 입력란에 **Ctrl+V**)으로 동작합니다.

- memoinall을 **관리자 권한으로 실행**한 경우 — Windows가 관리자 권한 앱에서는 공유 창을 띄우지 않습니다.
- Windows 공유 구성요소(`winrt`)가 없는 빌드이거나 공유 창을 열지 못한 경우

공유 창이 보이지 않거나 목록에 Teams가 없으면 memoinall의 **파일 위치 열기**를 눌러 선택된 파일을 Teams 채팅으로 끌어다 놓으세요.

첨부용 파일은 앱 데이터의 `teams-share` 폴더에 임시로 보관합니다. 만든 지 24시간이 지난 파일은 다음 앱 시작 또는 파일 공유 때 정리합니다. Windows 브라우저에서는 **첨부파일 다운로드**와 **Teams 새 채팅 열기**를 사용하세요. 다른 브라우저에서 JSON 파일 공유를 지원하면 기기의 공유 창이 열립니다. [Microsoft의 Teams 첨부파일 안내](https://support.microsoft.com/en-us/teams/files/share-files-in-microsoft-teams)

**보낼 때:** 내 메모에서 고르거나 공유 화면에서 태그·기간으로 범위를 좁히고 **무엇이 나가는지 보기**를 누릅니다.
목록 전체를 50건씩 표시하며 제목·본문 검색, 검색 결과 일괄 선택/해제, 선택한 메모만 보기를 지원합니다.
검색하거나 페이지를 바꿔도 체크는 유지됩니다. 선택 건수는 목록 전체 기준입니다.
의미 검색의 결과에는 관련성이 낮은 메모도 포함될 수 있으니 본문을 확인하고 제외하세요.

체크한 ID만 파일 저장·내용 복사에 전달합니다. 미리보기 이후 새 메모가 생겨도 추가되지 않습니다.
선택한 메모의 내용이 수정되거나 삭제되면 다시 확인하라는 메시지를 보여 줍니다.
범위 조건을 바꿨을 때도 목록을 다시 확인해야 합니다. 비밀번호와 파일 암호화는 기존과 동일합니다.
한 번에 1,000건까지 검토할 수 있으며 그 이상이면 태그·기간으로 범위를 좁혀주세요.

**받을 때:** `.json` 파일을 열고 필요한 메모만 체크합니다. 암호화된 파일은 비밀번호를 먼저 입력합니다.
이미 있는 메모·같은 내용·너무 짧은 내용은 건너뛰는 이유를 표시합니다. 선택이 0건이면 저장하지 않습니다.
파일 또는 가져오기 옵션이 바뀌면 다시 미리보기부터 확인합니다. OneNote 내보내기 파일·ENEX·받은 파일은 각각의 목록에서 필요한 메모를 골라 가져옵니다.

### 휴대폰 앱에서 QR로 받기 (휴대폰 → PC 한 방향)

휴대폰 앱에서 메모를 고르고 **PC로 보내기 → QR로 보여주기**를 누릅니다. PC에서 **가져오기·공유 → 휴대폰 QR·설치 → QR 찍기**를 열고 휴대폰 화면을 웹캠에 비춥니다.
네트워크를 거치지 않습니다. QR에는 공유 파일과 똑같은 내용(비밀번호를 정하면 암호화된 내용)이 압축되어 들어가고,
받은 뒤의 확인·선택·중복 처리도 파일과 같습니다. 한 장에 한글 약 370자가 들어가고, 넘치면 여러 장으로 나뉘어
자동으로 넘어갑니다(메모 10건 × 300자 ≈ 5장).

사내 정보 보호를 위해 **PC는 메모를 QR로 만들지 않고, 휴대폰 앱은 PC 메모를 받지 않습니다.**
휴대폰 앱이 없다면 같은 화면의 **휴대폰 앱 설치**가 설치 주소만 담은 QR을 보여줍니다. 자세한 내용은 [휴대폰 앱](mobile.md)을 보세요.

`tests/test_import_review_ui.py`는 Chromium에서 검색·페이지 이동·선택 유지와 실제 암호화 공유 파일의 내용을 확인합니다.
기존 `test_api.py`, `test_importers.py`, `test_exchange.py`, `test_ui.py` 회귀 테스트도 함께 실행합니다.
`tests/test_qr_share_ui.py`는 가짜 웹캠으로 휴대폰의 QR 여러 장(비밀번호로 잠근 것 포함)을 실제로 찍어 받고,
PC가 그리는 QR은 설치 주소뿐이고 메모를 QR로 내보내는 기능은 없는지 확인합니다.
