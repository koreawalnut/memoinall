# 휴대폰 앱

PC 앱과 **따로 쓰는** 휴대폰용 memoinall입니다. 메모와 일정은 그 휴대폰 안에만 저장되고, PC와는 네트워크로
연결되지 않습니다. 주고받기는 **휴대폰 → PC 한 방향**이며, 휴대폰 화면에 띄운 QR을 PC 웹캠으로 찍어서만 합니다.

웹 앱(PWA)이라 iPhone과 Android에서 모두 홈 화면에 설치해 앱처럼 쓰고, 설치한 뒤에는 인터넷 없이도 열립니다.

## 되는 것과 안 되는 것

| 기능 | 휴대폰 앱 | 비고 |
| --- | --- | --- |
| 메모 쓰기·고치기·지우기 | 됨 | 작성 중인 글은 자동 보관 |
| 검색 | 키워드 | 여러 단어는 모두 들어간 메모만. PC의 의미 검색은 없음 |
| 태그 | 됨 | 본문의 `#태그`가 자동으로 태그가 되고, 메모 화면에서 더하거나 뺄 수 있음 |
| 일정 | 직접 입력 | 달력·다가오는 일정·지난 일 중 안 끝난 것. 메모에서 자동으로 뽑지는 않음 |
| AI로 정리 | 내 API 키 | Gemini·ChatGPT·Claude. 고른 메모를 휴대폰에서 해당 회사로 바로 보냄 |
| PC로 보내기 | QR만 | 메모·일정. 휴대폰 → PC 한 방향. 파일·메신저·메일로는 보내지 않음 |
| PC 메모 가져오기 | 없음 | 사내 정보 보호를 위해 일부러 막음 |
| 백업·되살리기 | 파일 | 메모와 일정을 한 파일에. 되살리기는 이 앱이 만든 백업만 받음 |
| 음성 입력 | 키보드 마이크 | 휴대폰 키보드(Gboard·삼성 키보드 등)의 음성 입력을 그대로 씀 |
| 할 일 자동 추출·엑셀 취합·문서 가져오기 | 없음 | PC 앱에서 |

## 한 방향(휴대폰 → PC)인 이유

사내 정보가 개인 휴대폰으로 나가는 길을 이 앱이 만들지 않기 위해서입니다.

- **PC는 메모를 QR로 만들지 않습니다.** PC가 그리는 QR은 휴대폰 앱 설치 주소 하나뿐이고,
  QR 그리기 라이브러리도 그 창을 열 때만 싣습니다.
- **휴대폰은 QR을 읽지 않습니다.** 카메라로 받는 기능과 QR 인식 라이브러리가 휴대폰 앱에 없습니다.
- **휴대폰은 PC 공유 파일을 받지 않습니다.** 되살리기는 이 앱이 만든 백업(표시 `"backup": "memoinall/mobile-backup"`)만
  받고, PC가 내보낸 파일은 비밀번호로 열어도 거절합니다.
- **휴대폰 → PC도 QR로만 보냅니다.** 메신저·메일 서버를 거치는 파일 공유 버튼은 두지 않았습니다.

막을 수 없는 것도 있습니다. PC 화면을 사진으로 찍거나 내용을 손으로 옮겨 적는 것, PC 앱의 기존
**파일로 저장·내용 복사**(동료와 주고받기)로 만든 파일을 다른 경로로 옮기는 것은 이 앱이 막지 못합니다.

## 만들기

```bash
python build_mobile.py                # → dist/mobile/
python build_mobile.py --out 다른/폴더
```

결과 폴더(약 200KB)에는 정적 파일만 있습니다. 서버 코드는 없습니다. 버전은 파일 내용의 해시라서
내용이 바뀌었을 때만 휴대폰이 새 버전을 받습니다.

QR 모듈(`memoinall/static/qrshare.js`)과 QR 그리기 라이브러리는 PC 앱의 파일을 빌드할 때 가져옵니다.
`mobile/`에 복사본을 두지 않으므로 한쪽만 고쳐 형식이 어긋나는 일이 없습니다.

## 올리기 (GitHub Pages)

설치·오프라인 실행은 **HTTPS 주소**에서만 동작합니다. 무료 플랜은 공개 저장소에서만 Pages를 쓸 수 있으므로,
PC 앱 소스가 있는 저장소는 비공개로 두고 **빌드 결과만 담은 공개 저장소**(`kbiwalnut/mobile`)에 올립니다.
올라가는 것은 앱 코드와 아이콘뿐이고, 메모·일정·AI 키는 각 휴대폰의 브라우저 저장소(IndexedDB)에만 있습니다.

**처음 올릴 때**

```powershell
python build_mobile.py --out ..\memoinall-mobile
cd ..\memoinall-mobile
git init -b main
git add -A
git commit -m "memoinall 휴대폰 앱 배포"
git remote add origin https://github.com/kbiwalnut/mobile.git
git push -u origin main
```

그다음 저장소의 *Settings → Pages*에서 **Source: Deploy from a branch**, **Branch: main / (root)** 를 고르고
저장합니다. 1~2분 뒤 `https://kbiwalnut.github.io/mobile/`이 열립니다.

**업데이트할 때**

```powershell
python build_mobile.py --out ..\memoinall-mobile
cd ..\memoinall-mobile
git add -A
git commit -m "휴대폰 앱 업데이트"
git push
```

빌드는 `.git`·`README.md`·`CNAME`은 남기고 나머지만 바꿉니다. 비어 있지 않은데 이전 빌드가 아닌 폴더나
소스 폴더에는 빌드하지 않습니다. 휴대폰은 다음에 앱을 열 때 새 버전을 받고
“새 버전을 받았습니다 — 앱을 다시 열면 적용됩니다”를 보여줍니다.

**주의**

- 브라우저는 저장소를 **도메인 단위**로 나눕니다. `kbiwalnut.github.io` 아래에 다른 Pages 사이트를 올리면
  그 사이트가 이 앱의 메모·AI 키를 읽을 수 있습니다. 이 계정(조직)에는 이 앱만 올리세요.
- 이 저장소에 쓸 수 있는 사람은 앱 코드를 바꿀 수 있습니다. 계정·조직에 **2단계 인증**을 켜 두세요.
- 페이지에는 검색엔진 수집 거부(`noindex`)를 넣었습니다. 주소를 아는 사람이 열어도 빈 앱이 열릴 뿐
  다른 사람의 메모는 볼 수 없습니다.

다른 곳에 올려도 됩니다. Cloudflare Pages·Netlify는 폴더를 끌어다 놓으면 HTTPS 주소가 생기고 저장소를 공개하지 않아도 됩니다.

## 휴대폰에 설치

앱 스토어 파일은 없고, 주소를 열어 홈 화면에 추가하는 방식입니다. 주소를 치지 않아도 되게 PC 앱이 QR을 보여줍니다.

1. PC 앱의 **가져오기·공유 → 휴대폰 QR·설치**에서 **설치 QR 보기**를 누릅니다.
   QR에는 설치 주소만 들어 있고 메모는 들어 있지 않습니다.
2. 휴대폰 기본 카메라로 QR을 찍어 주소를 엽니다.
3. 앱 맨 위의 안내를 따릅니다.
   - **Android (Chrome·삼성 인터넷):** **홈 화면에 설치** 버튼을 누릅니다. 버튼이 없으면 브라우저 메뉴(⋮) → **앱 설치**.
   - **iPhone:** Safari 아래쪽의 공유 버튼 → **홈 화면에 추가**.
   - 카카오톡·네이버 앱 안의 브라우저로 열리면 설치할 수 없다고 알려줍니다. **다른 브라우저로 열기**를 누르세요.

설치하면 안내는 사라지고, **×**로 닫아도 다시 나오지 않습니다. 설치 방법은 **설정 → 설치**에서도 볼 수 있습니다.

PC 앱의 설치 주소는 기본 `https://kbiwalnut.github.io/mobile/`입니다. 다른 곳에 올렸다면 설치 QR 창의 **주소 바꾸기**나
환경변수 `MEMOINALL_MOBILE_URL`로 바꿉니다(https 주소만 받습니다).

설치한 앱은 브라우저가 저장 공간을 임의로 지우지 않도록 자동으로 요청합니다. **설정 → 자동 삭제 방지**에서 상태를 볼 수 있습니다.

## 쓰는 법

- **메모:** 위 칸에 적고 **저장**. 말로 쓰려면 키보드의 🎤(Android 키보드 마이크, iPhone 받아쓰기)를 누르세요.
  목록을 누르면 고치기·태그·PC로 보내기·AI로 정리·삭제를 할 수 있습니다.
  **선택**을 누르면 여러 개를 골라 한꺼번에 보내거나 정리하거나 지웁니다.
- **일정:** 날짜를 누르면 그날의 일정과 **이날 작성한 메모**가 보입니다. 메모가 있는 날짜에는 **▤**가 표시되고 제목을 누르면 원문을 열 수 있습니다. **+ 일정 추가**로 새 일정을 입력하고 체크하면 끝낸 일로 표시됩니다.
  **다가오는 일정 → PC로 보내기**(또는 일정 화면의 **PC로 보내기**)로 PC에 보냅니다.
- **보내기·백업:** 보낼 메모 고르기, 백업 파일 만들기·되살리기.
- **설정:** AI 서비스·키·모델, 저장 공간, 설치, 모든 데이터 지우기.

휴대폰의 뒤로 가기는 열려 있는 창을 닫습니다.

## PC로 보내기

1. 휴대폰에서 메모를 고르고 **PC로 보내기 → QR로 보여주기**. 비밀번호를 정하면 암호화됩니다.
   일정은 **일정 → 다가오는 일정 → PC로 보내기**에서 보낼 일정을 고릅니다(기본은 오늘 이후의 끝내지 않은 일정).
2. PC 앱 **가져오기·공유 → 휴대폰 QR·설치 → QR 찍기**를 누르고 휴대폰 화면을 웹캠에 비춥니다.
3. PC가 받은 목록을 보여주면 필요한 것만 체크해 가져옵니다. 이미 있는 것은 빼 둡니다.
   - 메모는 PC 메모로 들어갑니다.
   - 일정은 PC **일정**에 직접 추가한 일정과 똑같이 들어갑니다. 날짜는 예정일, 태그와 끝냄 여부는 그대로이고,
     시각은 이름 앞에(예: `10:30 고객사 방문`), 일정 메모는 함께 저장되는 메모에 붙습니다.
     같은 일정을 다시 보내도 PC에는 한 번만 들어갑니다. 휴대폰에서 고친 뒤 다시 보내도 PC 일정은 바뀌지 않으니 PC에서 고치세요.

QR 한 장에 한글 약 370자가 들어갑니다. 넘치면 여러 장으로 나뉘어 1.1초마다 자동으로 넘어가고,
PC는 순서와 상관없이 모읍니다(메모 10건 × 300자 ≈ 5장). 40장을 넘으면 나눠서 보내라고 안내합니다.

## 보안·주의

- **데이터는 휴대폰에만 있습니다.** 앱을 지우거나 브라우저의 사이트 데이터를 지우면 메모도 사라집니다.
  가끔 **백업 파일 만들기**를 하세요. 마지막 백업 시각이 보내기·백업 화면에 보입니다.
- **QR·백업 비밀번호**는 PC 앱의 공유 파일과 같은 방식입니다(scrypt로 키를 만들고 AES-256-GCM으로 암호화).
  비밀번호 없이 보내면 휴대폰 화면을 찍은 누구나 읽을 수 있습니다.
- **키보드 음성 입력**은 키보드 설정에 따라 음성이 Google·삼성·Apple 서버로 갈 수 있습니다. Gboard는 음성 입력 설정에서
  한국어 오프라인 인식을 받아 두면 휴대폰 안에서 처리됩니다. 메뉴 이름과 지원 여부는 기종·버전마다 다릅니다.
- **AI로 정리**를 누르면 고른 메모가 설정한 회사(Google·OpenAI·Anthropic)로 전송됩니다. 누를 때만 보냅니다.
  API 키는 휴대폰의 앱 저장소에 저장됩니다.

## 개발 메모

- `mobile/index.html`·`app.js`: 화면과 동작. 저장소는 IndexedDB(`memos`·`events`·`kv`).
- `mobile/exchange.js`: PC `exchange.py`와 같은 공유 형식. 같은 메모는 같은 uid가 되도록 정리 규칙까지 맞췄습니다.
- `memoinall/static/qrshare.js`: QR 형식 `MI1:<묶음>:<번호>:<전체>:<조각>`. 내용은 JSON 공백 제거 → deflate-raw
  → Base45(RFC 9285) → QR 영숫자 모드입니다. 휴대폰은 `show`(그리기)만, PC는 `scan`(웹캠 인식)만 씁니다.
  PC의 인식은 BarcodeDetector가 있으면 쓰고, 없으면 jsQR을 그때 불러옵니다.
- `mobile/sw.js`: 앱 파일만 캐시합니다. 다른 주소(AI 서버)로 가는 요청은 건드리지 않습니다.

```bash
python tests/test_mobile.py         # 빌드 결과 · QR 형식 · PC와 공유 형식 일치 · 백업 표시 (Node 필요)
python tests/test_mobile_ui.py      # 휴대폰 크기 Chromium으로 전체 흐름 · 한 방향 확인 · 오프라인
python tests/test_qr_share_ui.py    # PC 앱이 가짜 웹캠으로 휴대폰 메모·일정 QR 받기 · 설치 주소 QR · 메모 QR은 없음
python tests/test_schedule_receive.py  # 받은 일정 검증 · 비밀번호 · PC 일정으로 넣기 · 중복 방지
```

AI 요청은 테스트에서 가짜 응답으로 확인합니다. 실제 키로 각 서비스에 보내 본 것은 아닙니다.
