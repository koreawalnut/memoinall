# 엑셀 폴더 취합 설계안

상태: 1차 구현 · 2026-11-09 (구현한 범위와 설계와 달라진 점은 [10절](#10-구현-현황-2026-11-09)). 사용자가 지정한 주 대상은 **같거나 비슷한 열을 가진 목록형 엑셀**이다.
화면 흐름은 같은 폴더의 [화면 시안](excel-collection-preview.html)에서 예시 데이터로 확인할 수 있다.

## 1. 목표와 범위

부서별 실적·명단·신청 내역을 한 표로 모으고, 누락을 확인한 뒤 AI로 보고서와 후속 업무를 정리한다.
기본 흐름은 **폴더 선택 → 취합 확인 → 결과 활용**이다. 평소 메모 작성 화면과 AI 정리 화면은 유지한다.

첫 버전은 `.xlsx`, `.xlsm`, `.xls`의 목록형 표를 대상으로 한다. 시트마다 표 하나가 있는 형태를 우선 지원한다.
같은 열 이름은 순서가 달라도 맞춰 합친다. 비슷한 이름은 연결을 제안하고 사용자가 확인한다.
신청서처럼 특정 칸에 값이 흩어진 양식, 한 시트의 여러 표, 복잡한 다단 머리글은 확인이 필요한 대상으로 표시한다.
이를 목록형으로 억지 변환하지 않는다. 고정 셀 지정 방식은 후속 개발 범위다.

## 2. 기존 앱과의 연결

현재 `memoinall/documents.py`는 엑셀 한 파일을 읽어 시트별 텍스트 메모로 변환한다.
`static/index.html`의 문서 가져오기에서 파일을 고르고, 저장한 메모 ID를 기존 AI 정리에 넘긴다.
`generate.py`의 AI 자료 묶음은 검색 건수와 읽을 분량에 제한이 있다.
따라서 이 경로에 여러 파일만 추가하면 전체 건수·금액을 정확하게 취합하는 기능이 되지 않는다.

새 기능에는 **행·열을 보존하는 취합 자료 저장소와 전체 행 대상 계산**이 필요하다.
기존 문서 가져오기는 계속 제공한다. 새 버튼은 기존 가져오기 영역에만 추가한다.

| 위치 | 변경 제안 |
|---|---|
| 가져오기·공유 → 문서 가져오기 | `파일 선택` 옆에 `엑셀 폴더 취합` 버튼 하나 추가 |
| 취합 작업 화면 | 선택·확인·결과를 하나의 화면 안에서 단계별 표시 |
| 메모 목록 | 저장한 취합 자료를 대표 메모 한 개로 표시. 행마다 메모를 만들지 않음 |
| 대표 메모 | `취합표 보기`, `이 자료를 AI로 정리`, 접힌 `더 보기`에 엑셀 저장·다시 취합 |
| 기존 AI 정리 | `사용할 자료: 11월 신청 내역 · 파일 12개 · 1,248행` 표시 후 기존 요청·편집·저장 이용 |

대표 메모에는 제목, 집계 요약, 취합 시각, 자료 연결을 넣고 `#엑셀취합`과 사용자 태그를 붙인다.
태그는 자료를 찾는 데 사용한다. 실제 AI 실행 대상은 선택한 취합 자료의 정확한 버전으로 고정한다.
대표 메모를 복사·수정하더라도 원본 표의 숫자가 자동으로 바뀌지 않는다.

## 3. 사용 흐름과 문구

### 3.1 폴더 선택

- 제목: `엑셀 폴더 취합`
- 설명: `같은 항목을 가진 엑셀을 한 표로 모으고, AI로 정리할 수 있어요.`
- 주 버튼: `폴더 선택`
- `하위 폴더도 포함`은 기본 해제. 상세 옵션은 접어 둔다.
- 데스크톱은 운영체제 폴더 선택 창을 사용한다. 브라우저에서는 폴더 업로드를 지원하고, 지원하지 않는 환경은 여러 파일 선택으로 대체한다.
- 엑셀 파일만 찾고 `~$` 임시 파일은 제외한다. 숨김 시트는 기본 제외하고 제외 내역에 남긴다. 다른 폴더를 가리키는 링크는 따라가지 않는다.
- 읽기는 백그라운드에서 진행한다. `12개 중 5개 읽는 중`과 `취소`를 제공하고 메모 작성은 계속 가능하게 한다.

### 3.2 취합 확인

상단에 `12개 파일 · 1,248행 · 확인 필요 2개`처럼 범위와 문제 수를 먼저 보여준다.
전체 파일 목록과 `확인 필요만 보기`를 제공한다. 파일 안에는 시트별 체크와 미리보기가 있다.
같은 파일 이름이 여러 폴더에 있으면 `영업팀/실적.xlsx`처럼 상대 경로로 구별한다.

| 확인 항목 | 기본 처리 | 사용자에게 보이는 표현 |
|---|---|---|
| 열 이름과 순서 | 앞뒤 공백·줄바꿈 정리 후 이름이 정확히 같은 열 연결. 열 순서는 무관 | 별도 설정 없이 표 표시 |
| 비슷한 열 이름 | 예: `소속` → `부서`를 후보로 제안. 확인 전 미연결 | `같은 항목인가요?` → `같은 항목으로 사용` |
| 빠진 열·추가 열 | 빠진 값은 빈칸, 추가 열은 유지하는 안을 보여줌. 표 구조 차이는 확인 대상 | `이 파일에는 ‘신청일’이 없어요` |
| 제목이 표 위에 있음 | 머리글 후보를 제안하고 실제 행 번호와 미리보기 제공 | `항목 이름이 있는 행: 3행` |
| 이름이 없거나 중복된 열 | 자동 결합하지 않고 사용자가 이름·연결 결정 | `항목 이름을 확인해 주세요` |
| 합계·소계 행 | 후보 표시. 일반 데이터와 구별해 포함 여부 확인 | `합계로 보이는 2행이 있어요` |
| 중복으로 보이는 행 | 표시만 하고 기본 유지. 실제 중복 여부는 사용자가 결정 | `내용이 같은 3행 확인` |
| 파일 읽기 실패·암호 | 실패 이유와 대상 파일 표시. 조용히 건너뛰지 않음 | `읽지 못한 파일 1개` |

연결·제외는 행과 열의 원본을 보존하는 취합 규칙으로 저장한다. 이름이 비슷하다는 이유만으로 서로 다른 금액·통화·단위를 섞지 않는다.
문제가 있는 파일은 수정하거나 체크를 해제해야 저장할 수 있다. 해제한 파일은 결과에도 제외 사유가 남는다.
빈칸처럼 취합 자체를 막지 않는 문제는 저장할 수 있지만, 계산에 미치는 영향을 결과에 표시한다.

하단 주 버튼은 `12개 파일 · 1,248행 취합하기`처럼 실제 선택 범위를 명시한다.
일부 파일을 제외하면 버튼·결과에 그 범위를 반영한다. 미리보기만으로 메모나 정식 취합 자료를 저장하지 않는다.

### 3.3 결과 활용

기본 화면에는 제목, 파일·행 수, 확인 사항, 합쳐진 표를 표시한다. 큰 표는 페이지 단위로 읽는다.
처음부터 차트·지표·설정 패널을 늘어놓지 않는다.

- 주 버튼: `이 자료를 AI로 정리`
- 보조 버튼: `엑셀로 저장`
- 접힌 `취합 기준`에서 `부서별 / 신청금액 합계`처럼 묶을 항목과 계산할 항목을 선택한다.
- 출처 열은 접어 두고 행의 `출처 보기`에서 파일·시트·행 번호를 확인한다.
- `더 보기`에서 `같은 폴더로 다시 취합`, `취합 방법 저장`, `제외 내역`을 연다.

저장한 결과는 앱을 재실행해도 열 수 있다. 원본 폴더가 없어도 저장 당시의 행과 집계는 확인 가능하다.
다시 취합할 때만 원본 폴더가 필요하다.

## 4. 숫자와 범위의 정확성

**앱이 전체 대상 행으로 계산하고, AI는 계산 결과를 설명한다.** 검색된 일부 메모만 보고 전체 합계를 추정하지 않는다.

- 합계·평균·건수·고유값 수·빈칸 수·그룹별 내역을 허용된 계산 기능으로 구한다.
- `건수`는 행 수다. `인원 수`는 사번 등 사용자가 정한 식별 항목의 고유값 수로 구분한다. 기준 없이 이름만으로 인원 수를 단정하지 않는다.
- 금액은 이진 부동소수점 누적을 피하고 정해진 소수 자릿수·단위에 따라 계산한다. 원본값, 표시 문자열, 변환값을 함께 보관한다.
- `00123` 같은 식별자와 숫자 서식으로 표현한 앞자리 0을 보존한다. 식별자는 자동 합산 대상에서 제외한다.
- 비어 있음, 숫자 0, 셀 오류, 변환 실패, 수식 결과 없음은 서로 다른 상태로 관리한다.
- 계산 불가 행을 0으로 취급하지 않는다. `금액 확인 가능 1,240행 / 값 확인 필요 8행`처럼 분모와 제외 이유를 표시한다.
- 통화·단위가 다른 열은 자동 환산하지 않는다. 퍼센트의 단순 평균과 가중 평균도 구분한다.
- 날짜는 엑셀 날짜 형식과 통합문서 날짜 기준을 반영한다. `이번 달`은 사용자가 고른 `신청일` 등 표의 날짜 항목에 적용한다. 메모 저장일과 혼용하지 않는다.
- 숨긴 행이나 필터로 가려진 행은 기본 포함하되 그 기준을 안내하고 포함 수를 표시한다. 숨김 시트 제외 정책과 구별한다.
- 합계·소계 후보 및 반복 머리글은 사용자가 제외 규칙을 확인해야 한다. 확인되지 않은 합계 행을 다시 합산하지 않도록 계산 전 확인 대상으로 둔다.
- 원본에 있던 수식은 저장된 계산 결과만 읽는다. 결과가 없으면 계산 불가, 저장값이 있어도 최신 계산 여부는 보장하지 않는다. `엑셀에서 계산 후 저장한 파일로 다시 가져오기`를 안내한다.
- 매크로 실행·외부 연결 새로고침·임의 코드 실행은 수행하지 않는다.

현재 사용 중인 openpyxl도 수식을 직접 계산하지 않는다. 이는 가져오기 옵션만으로 해결되는 문제가 아니다.
근거: [openpyxl 수식 문서](https://openpyxl.readthedocs.io/en/stable/simple_formulae.html).

## 5. AI 사용 설계

AI 정리 진입 시 자료 버전, 적용 필터, 사용한 파일·행 수, 제외 내역을 고정한다.
요청문 아래에는 세 가지 시작 문구만 둔다.

| 시작 문구 | 결과 |
|---|---|
| `현황 요약` | 확인된 집계와 주요 차이를 요약. 부서 열 등 필요한 항목이 없으면 먼저 선택 요청 |
| `확인할 내용 찾기` | 정해진 규칙으로 찾은 빈칸·중복 후보·오류를 묶어 설명. AI가 제안한 추가 검토 사항은 별도 표시 |
| `보고서 초안` | 집계표를 근거로 보고용 문장, 확인 사항, 후속 할 일 제안 |

예: `부서별 신청금액과 미처리 내역을 정리해줘` → `부서`, `신청금액(원)`, `처리상태`를 확인 → 전체 선택 행에서 집계 → AI가 보고서 초안 작성.
계산 항목이 명확하지 않으면 `금액 항목 선택` 같은 짧은 질문으로 해결한다.

첫 버전은 미리 제공하는 집계 기능만 호출한다. 자연어로 요청했다고 임의 Python·SQL을 실행하지 않는다.
지원하지 않는 분석은 추측한 수치를 출력하지 않고 필요한 집계 기준을 선택하게 한다.
AI 결과에 수치를 삽입할 때는 실제 집계 지표 ID와 값이 연결되도록 하고, 알려진 값과 불일치하는 숫자는 검증 대상으로 표시한다.

AI에 전달하는 내용:

1. 취합 자료 이름·버전, 날짜·행 필터, 파일/시트/행 포함·제외 수.
2. 전체 해당 행으로 계산한 지표와 계산 기준, 계산 불가 건수.
3. 요청과 관련된 원문 행·텍스트, 각 행의 출처 ID.
4. `전체 숫자 집계`와 `일부 원문 참고`의 범위 차이.

설명용 예시 행만 읽었다면 전체 행의 서술 내용까지 확인했다고 표현하지 않는다.
전체 자유서술을 읽어야 하는 분석은 후속 단계에서 묶음별 처리·처리 건수 추적을 추가한다.
토큰 제한 때문에 그룹별 집계가 다 들어가지 않으면 전체 합계와 명시한 상위 항목·나머지 합계를 제공하고, 전체 표 링크를 남긴다.

AI는 기존처럼 사용자가 `정리하기`를 누를 때 호출한다. 파일 읽기·열 연결·숫자 취합은 로컬에서 수행한다.
표 안의 문장은 분석 대상 데이터로 취급한다. 셀 안에 적힌 지시를 실행하거나 외부 주소에 자동 접근하지 않는다.
출처 클릭 시 저장 당시 표의 행을 연다. 기존 메모 참고 문헌과 취합 행 출처를 구별한다.

## 6. 재취합·공유·기존 업무 설정

같은 폴더를 다시 읽을 때 기존 표에 무조건 덧붙이지 않고, 새 취합 버전을 만든다.
사용자가 확인한 뒤 대표 메모의 현재 자료 연결을 새 버전으로 바꾼다. 이전 AI 결과는 당시 버전을 계속 참조한다.
원본이 동일한 재실행은 중복 버전을 만들지 않을 수 있지만, 다른 경로에 있는 동일 내용 파일은 같은 파일로 합치지 않는다.
파일 안의 중복 행도 사용자가 정한 기준 없이는 지우지 않는다.

폴더가 바뀌었거나 없어졌으면 다시 선택한다. 폴더 감시·자동 취합은 첫 버전에 넣지 않는다.
`취합 방법 저장`에는 시트 선택 규칙, 머리글 행, 열 연결·자료형·제외 규칙, 집계 기준을 저장한다.
다음 실행에 새 구조가 나타나면 이전 규칙을 무조건 적용하지 않고 확인 화면으로 보낸다.

기존 `자주 하는 업무`의 요청문·출력 형식은 재사용할 수 있다. 자료 바인딩은 추가 설계가 필요하다.
현재 설정 파일의 필드는 엄격히 검증되므로 별도 버전 규격 없이 새 필드를 섞지 않는다.
업무 기간 조건도 취합표의 날짜 항목을 선택한 경우에만 적용한다.

공유는 두 종류로 구분한다.

- `취합 방법 공유`: 설정만 전달. 실제 행, 절대 폴더 경로, 로컬 자료 ID는 제외. 받는 사람이 자기 폴더를 선택한다.
- `엑셀로 저장`: 사용자가 확인한 실제 데이터를 전달. `취합표`, `집계`, `확인 사항`, `출처` 시트를 포함한다.

내보내기는 원본 수식을 실행 가능한 형태로 복사하지 않고 값·텍스트로 작성한다.
대표 메모만 공유했을 때 상대 PC에 내부 자료 연결이 생긴 것처럼 표시하지 않는다.
백업은 취합 자료와 버전도 포함해야 한다. 삭제는 AI 결과의 근거 연결 정책을 함께 정하고, 참조 중인 자료를 조용히 지우지 않는다.

## 7. 저장·실행 구조 제안

아래 명칭은 내부 설계용이며 사용자 화면에 노출하지 않는다. 첫 구현은 기존 SQLite와 문서 파서 의존성을 활용한다.

| 구성 | 역할 |
|---|---|
| `collections` | 제목, 대표 메모, 현재 확정 버전, 취합 규칙 |
| `collection_versions` | 고정된 입력·규칙의 버전, 생성 시각, 포함/제외 통계, 전체 지문 |
| `collection_files` / `collection_sheets` | 상대 경로·파일 지문, 시트, 머리글·읽기 상태·문제 내역 |
| `collection_columns` | 원본 열과 연결된 항목 ID, 표시명, 자료형·단위·변환 규칙 |
| `collection_rows` | 파일·시트·원본 행 번호, 원본값·표시값·변환값, 포함 여부와 이유 |
| `collection_jobs` | 읽는 중/확인 필요/저장 완료/취소/실패, 진행 수, 임시 자료 수명 |
| `collection_aggregates` | 자료 버전·필터·집계 조건으로 식별한 계산 결과와 근거 행 범위 |

원본값·표시값을 JSON으로 보관하고, 집계는 자료형을 확인한 값으로 수행한다.
금액을 SQLite REAL 또는 JSON 문자열 정렬만으로 계산하지 않는다. 초기에는 행을 순차 처리하는 Decimal 집계도 가능하다.
원본 엑셀 전체 파일을 영구 복제하지 않고, 확정한 표 데이터와 출처·오류 정보를 보관한다.
임시 작업 자료는 취소·실패·기한 경과 시 정리하고, 앱 재실행 때 완료 자료와 혼동하지 않는다.

후보 모듈: `excel_collection.py`(구조 추출), `collections.py`(저장·작업), `collection_analysis.py`(계산·AI 근거), `static/collections.js`(단계 화면).
기존 `documents.py`의 읽기 제한과 형식 처리 코드는 재사용 가능한 부분만 분리한다. 텍스트 추출 결과를 다시 표로 파싱하지 않는다.

API 흐름 초안:

```text
POST /api/collections/jobs                  선택한 입력으로 작업 시작
GET  /api/collections/jobs/{id}             진행·오류 확인
POST /api/collections/jobs/{id}/cancel      취소
GET  /api/collections/jobs/{id}/preview     파일·시트·표 미리보기
PUT  /api/collections/jobs/{id}/rules       열 연결·선택·제외 규칙 적용
POST /api/collections/jobs/{id}/commit      확인한 규칙 버전을 지정해 확정
GET  /api/collections/{id}/versions/{v}/rows  페이지별 표 조회
POST /api/collections/{id}/versions/{v}/aggregate  허용된 집계만 실행
POST /api/generate                         해당 자료 버전과 집계를 명시해 기존 AI 흐름 이용
```

데스크톱 폴더 선택 결과는 서버가 발급하는 작업 토큰으로 연결한다. 임의 절대 경로를 받는 범용 파일 읽기 API를 만들지 않는다.
폴더 하위만 열도록 경로·링크를 확인한다. 브라우저 입력은 상대 경로를 검증한 파일 스트림으로 처리한다.
미리보기는 읽은 입력 바이트의 지문에 고정한다. 확정 단계에서 원본을 재독하는 구현이라면 지문 변경을 감지해 재확인한다.
파일을 읽는 동안 DB 쓰기 잠금을 유지하지 않는다. 작은 단위로 임시 저장하고 확정 시 원자적으로 공개한다.
취소한 작업은 정식 목록과 AI 자료에 나타나지 않는다.

## 8. 성능과 처리 한도

앱 시작 때 폴더를 스캔하거나 새 취합 자료를 모두 임베딩하지 않는다. 사용자 실행 시 한두 파일씩 읽고 작업량을 제한한다.
한 번에 모든 파일을 메모리에 올리지 않고, 행 저장과 미리보기를 나눠 처리한다. 취합 숫자 분석에는 벡터 DB 준비를 요구하지 않는다.

첫 개발의 보수적 한도 제안은 한 번에 100개 파일·총 200MB·100만 셀, 파일당 기존 20MB·20만 셀 제한 유지다.
압축 해제 크기 등 기존 방어적 제한도 유지한다. 이는 성능 보장 수치가 아니며 대표 PC에서 측정 후 조정한다.
한도를 넘으면 임의로 뒷부분을 잘라 성공 처리하지 않고, 초과 지점과 나눠 가져오는 방법을 안내한다.

진행 중에도 메모 입력과 저장이 가능한지, 취소가 일정 행 묶음마다 반영되는지 측정한다.
대용량 자료를 저장한 뒤에도 앱 초기 화면이 빨리 열리는지 회귀 검증한다.

## 9. 개발 순서와 완료 조건

1. 폴더 읽기·단계 화면·구조화 저장·열 연결·출처·재취합 버전을 먼저 구현한다.
2. 전체 행 집계·확인 사항·엑셀 내보내기를 구현하고 수치를 검증한다.
3. 고정된 집계·근거를 기존 AI 정리·편집 이력과 연결한다.
4. 취합 방법 저장·공유와 기존 업무 설정 재사용을 붙인다.

**첫 사용 가능한 배포 범위는 1~3을 모두 포함**한다. 고정 셀 양식, 자동 폴더 감시, 전체 자유서술 분류는 후속 범위다.

필수 검증:

- 서로 다른 하위 폴더의 같은 파일명, 같은 열의 다른 순서, 비슷한 이름·중복 머리글·추가/누락 열.
- 빈 시트·숨김 시트/행·반복 머리글·합계 행·정상적인 중복 행, 일부 파일 실패 후 명시적 제외.
- 앞자리 0·소수 금액·음수·날짜 기준·단위/통화 혼합·수식 저장값 없음·셀 오류.
- 알려진 전체 정답과 합계/건수 일치. 검색·토큰 예산이 작아도 집계 결과가 변하지 않음.
- 발견/선택/제외/실패 파일 수와 포함/제외/계산 불가 행 수가 결과·AI 근거·내보내기에서 일치.
- 취소·중복 확정·앱 종료·원본 변경·재취합 후에도 이전 AI 결과의 출처 버전 보존.
- 백업·복원·메모만 공유 시 자료 연결 상태, 내보낸 셀 텍스트가 수식으로 실행되지 않음.
- 기존 메모 작성·저장·문서 한 파일 가져오기·AI 태그 범위·저장한 업무 기능 회귀 검증.

경진대회 검증은 동일 예제에 대해 `파일 열기 → 복사·취합 → 누락 확인 → 보고서 작성`의 수작업 시간과 앱 사용 시간을 측정한다.
AI 실행 시간뿐 아니라 사용자의 검토·수정 시간을 포함한다. 절감률은 측정 후 기재하고, 알려진 정답과 누락 발견 결과도 함께 보여준다.

참고: 동일한 구조의 폴더 내 파일을 미리보기 후 하나의 표로 결합하는 방식은
[Microsoft Power Query의 파일 결합 흐름](https://learn.microsoft.com/en-us/power-query/combine-files-overview)에서도 사용한다.
이 앱에서는 취합 결과의 출처 확인과 AI 보고서 작성까지 이어지는 간단한 흐름에 초점을 둔다.

## 10. 구현 현황 (2026-11-09)

9절의 첫 배포 범위 1~3을 구현했다. 진입점은 `가져오기·공유 → 문서 가져오기 → 엑셀 폴더 취합`이다.

| 구분 | 구현 내용 |
|---|---|
| 읽기 | `.xlsx`·`.xlsm`(openpyxl, 저장값만)·`.xls`(xlrd). 숨김 시트 제외, `~$` 임시 파일 제외, 하위 폴더는 옵션 |
| 확인 | 빠른 사용을 위해 **묻지 않고 자동 처리**한다: 비슷한 열 이름 연결(공백·괄호 차이, 동의어, 포함 관계. 단위가 다르면 연결 안 함), 표 위 제목 건너뛰기, 합계·반복 머리글 행 빼기, 추가 열은 새 항목·없는 열은 빈칸. 자동으로 맞춘 내용은 시트별로 접어 두고 바꿀 수 있다. 저장을 막는 것은 두 열을 같은 항목에 연결했을 때, 지정한 머리글 행이 비었을 때, 취합할 행이 없을 때뿐이다. 같은 이름의 시트는 한 번에 선택한다 |
| 저장 | 확인 화면의 revision 이 같을 때만 확정. 같은 요청 반복은 한 번만 저장. 대표 메모 1개(`#엑셀취합`) |
| 계산 | Decimal 합계·평균·최소·최대, 텍스트 숫자 변환 수, 빈칸·열 없음·셀 오류·수식 결과 없음을 따로 집계. 앞자리 0·사번류는 식별자 |
| 결과 | 50행 페이지 표, 행별 출처, 묶음 집계(묶을 항목·계산할 항목 선택), 뺀 행 보기, 파일별 취합 내역, 버전 선택, 삭제 |
| 내보내기 | `취합표 · 집계 · 확인 사항 · 출처` 시트. 텍스트는 문자열 셀로 써서 `=`로 시작해도 수식이 되지 않음. 데스크톱은 저장 대화상자 |
| AI | 자료 버전·묶음 기준을 고정해 기존 AI 정리 흐름 사용. 시작 문구 3개, 집계 근거 사본을 결과와 함께 보관(다듬기도 같은 근거), 집계에 없는 숫자 표시, `[C번호]` 출처 링크 |
| 다시 취합 | 같은 자료에 새 버전. 시트 선택·머리글 행·열 연결은 다시 적용하고 확인 표시와 합계 행 결정은 다시 받음. 대표 메모의 태그 유지 |

설계와 달라진 점:

- **확인 단계**: 3.2절의 '확인 전 미연결'·'포함 여부 확인'은 사용해 보니 확인할 것이 너무 많아, 자동 처리 후 알려 주는 방식으로 바꿨다(2026-11-09 사용자 요청).

- **폴더 선택**: 데스크톱 전용 폴더 대화상자·작업 토큰 대신, 브라우저와 WebView2 모두 폴더 업로드(`webkitdirectory`)로 상대 경로와 파일을 하나씩 보낸다. 서버는 절대 경로를 받지 않는다.
- **작업 자료**: `collection_jobs` 테이블 대신 서버 메모리에 둔다(최대 3개, 6시간). 앱을 다시 시작하면 확정 전 작업은 사라진다.
- **저장 구조**: `collections`·`collection_versions`·`collection_rows` 세 테이블로 줄였다. 파일·시트·열 정보와 통계는 버전의 JSON 에, 집계는 저장하지 않고 요청 때 계산해 메모리에 잠시 기억한다.
- **모듈 이름**: 표준 라이브러리 `collections` 와 겹치지 않게 `collection_store.py` 를 쓴다. 화면은 `static/collections.js`.

아직 하지 않은 것(후속 범위): 취합 방법 저장·공유와 `자주 하는 업무` 연결(4단계), 날짜 기준 기간 필터, 인원 수(고유값) 집계 선택,
백업·공유 파일에 취합 자료 포함, 숨긴 행 수 표시, 대용량 성능 측정과 한도 조정.
