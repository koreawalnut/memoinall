# 일정: 메모 속 할 일, 달력과 공유

상단 대메뉴 **일정**에서 바로 엽니다. 기존 **더 보기 → 할 일**을 옮기고 이름을 바꿨습니다.
기본 기능은 API 키나 모델 연결 없이 동작하며 메모 원문을 자동으로 고치지 않습니다.

## 메모 쓰기

| 메모 | 처리 |
|---|---|
| 금요일까지 보고서 보내야 함 | 보고서 보내기 · 금요일 마감 |
| 11월 10일 회의 내용을 11월 20일까지 정리해야 함 | 회의 날짜와 마감을 구분해 11월 20일 마감 |
| 내일 보고서 작성하기 | 내일 예정 · 마감일은 미정 |
| 금요일까지 보고서 제출 | ‘해야 함’ 없이 적은 행동도 금요일 마감으로 추출 |
| 다음 주쯤 자료 검토해야 함 | 다음 주 월~일 범위로 예정 · 특정 마감일을 만들지 않음 |
| 민수님에게 견적 요청함. 목요일까지 받기로 함 | 회신 대기 · 목요일에 다시 확인 |
| 견적 오면 비교해서 업체 정해야 함 | 기다리는 일 · 견적 도착 후 진행 |
| 김대리가 견적 보내야 함 | 확인 필요 · 내가 챙길 일인지 선택 |
| 회의 전까지 안건 정리해야 함 | 확인 필요 · 회의 날짜를 임의로 추정하지 않음 |

`[ ]`, `[x]`, `TODO:`와 기존 한국어 행동 표현도 지원합니다.
요일, 이번 주/다음 주/다다음 주의 요일, 오늘/내일/모레, 연월일을 처리합니다.
상대 날짜의 기준은 원래 메모 작성일이며, 재분석한 날로 밀리지 않습니다.
요일만 적으면 작성일을 포함한 다음 해당 요일입니다. `이번 주 금요일`은 그 주의 금요일입니다.
12월 메모의 연도 없는 1월 날짜는 다음 해, 1월 메모의 12월 날짜는 전년으로 해석합니다.
오래된 기록이나 해석과 다른 날짜는 ‘수정·날짜’에서 고칠 수 있습니다.

## 목록과 조작

- **오늘 챙길 일:** 오늘 마감, 기한이 지난 일, 다시 볼 날짜나 예정일이 된 일.
- **다가오는 일:** 앞으로 마감·예정·다시 볼 날짜가 있는 일.
- **기다리는 일:** 답변이나 선행 작업을 기다리며 다시 볼 날짜가 정해지지 않은 일.
- **일정 미정:** 행동은 있지만 날짜가 없는 일. ‘오늘 보기’로 오늘 목록에 올릴 수 있습니다.
- **확인 필요:** 다른 사람의 일, 가져온 자료의 문장, 모호한 기한. ‘내 할 일로’ 또는 ‘할 일 아님’으로 정리합니다.
- **완료 / 제외:** 처리한 항목을 다시 열 수 있습니다.

마감일과 다시 볼 날짜는 별도입니다. 금요일 마감인 일을 수요일에 다시 보도록 설정할 수 있습니다.
‘내일 다시 보기’를 눌러도 오늘 마감이거나 기한이 지난 일은 오늘 목록에 남습니다.
예정일이 지났는데 아직 끝나지 않은 일도 사라지지 않고 오늘 목록에서 확인할 수 있습니다.
오늘 할 일 숫자는 사용자 PC의 날짜를 기준으로 계산합니다. 각 분류는 50건씩 이동하며 건수는 전체 기준입니다.

‘수정·날짜’에서 이름·상태·예정일·예정 종료일·마감·다시 볼 날짜를 고칩니다. 빈 날짜는 미정입니다.
직접 고친 값은 자동 정리보다 우선합니다. ‘메모에서 다시 읽기’로 최신 규칙 추출 결과를 다시 적용할 수 있습니다.
AI가 정리한 값이 있으면 이 버튼은 ‘AI 정리값으로 되돌리기’로 표시됩니다.
최근 조작은 ‘되돌리기’로 취소할 수 있습니다. 원문과 출처는 ‘메모 근거 보기’에서 확인합니다.

## 상태 보존과 기존 데이터

기존 완료 체크와 ID를 유지하면서 새 저장 구조로 자동 이전합니다.
이전 규칙으로 분석된 메모는 시작 후 백그라운드 준비 또는 할 일 화면을 열 때 다시 분석합니다.
이때 임베딩을 다시 만들거나 메모 본문·작성일을 바꾸지 않습니다.

같은 메모 안에서 원문이 같거나, 날짜·태그·어미를 정리한 행동이 하나로 특정되면 동일한 할 일 ID를 유지합니다.
완료·제외·직접 고친 값도 유지됩니다. 본문에서 사라진 항목은 비활성화하고, 다시 나타나면 이전 결정을 복원합니다.
같은 행동이 여러 번 나오면 원문이 일치하는 항목만 연결해 서로의 완료 상태가 섞이지 않도록 합니다.
메모 삭제 시 관련 할 일도 삭제됩니다. 보관한 메모는 보드와 남은 할 일 집계에서 제외됩니다.

## 달력으로 보기

**일정**을 열면 **달력**이 먼저 표시됩니다. 상단의 **달력·목록**으로 전환할 수 있습니다.
다른 메뉴를 사용하다 일정으로 돌아와도 달력을 먼저 엽니다. 마지막으로 선택한 월과 날짜는 유지합니다.

- **마감:** 끝내야 하는 날. 기한이 지났으면 붉은색으로 표시합니다.
- **다시 보기:** 이 일을 챙기기로 한 날. 같은 일의 마감과 다른 날짜에 표시할 수 있습니다.
- **예정:** 메모에서 읽은 실행 예정일.
- **기간 중:** ‘다음 주쯤’처럼 범위로 적은 일정. 기간에 속한 날짜들에 표시하지만 매일 반복하는 일은 아닙니다.
- **외부 일정:** 가져온 캘린더 일정. 할 일과 구분해 표시하며 남은 할 일 숫자에는 포함하지 않습니다.

넓은 화면에서는 달력 오른쪽에 선택한 날짜의 일정을 나란히 표시합니다. 좁은 화면에서는 달력 아래로 이어집니다.
날짜별 목록에서 완료·제외·날짜 수정·원문 확인을 할 수 있습니다. 오늘은 채워진 원으로, 선택한 날은 테두리로 구분합니다.
같은 일의 마감과 다시 볼 날짜가 겹치면 그날 한 건으로 세며, 두 의미를 함께 표시합니다.
한 달의 할 일 수도 중복 없이 셉니다. 한 날짜에 많은 일이 있으면 셀에 추가 건수를 표시하고 날짜별 목록은 50건씩 이동합니다.
‘다시 볼 날짜’를 지정하면 달력에서는 원래 예정일보다 그 날짜를 우선 표시하며, 마감일은 별도로 유지합니다.

이전 달·다음 달·오늘 버튼으로 이동하며, 날짜에 키보드 초점을 두고 방향키로 하루 또는 한 주씩 이동할 수 있습니다.
달력에서 **▤** 표시가 있는 날을 누르면 **이날 작성한 메모**에서 작성 시각과 제목을 볼 수 있습니다. 제목을 누르면 원문이 열립니다. 달력의 태그 필터는 메모에도 적용됩니다.
예를 들어 월요일 회의 메모에 금요일 마감이 적혀 있다면, 메모는 월요일에, 마감은 금요일에 표시됩니다.
좁은 화면에서는 날짜 칸에 종류별 건수와 나머지 건수를 표시하고, 선택한 날짜의 상세 목록에서 전체 이름을 확인합니다.
외부 일정의 시각은 넓은 달력 칸과 상세 목록에 표시합니다. 화면 색상은 시스템의 밝은/어두운 테마를 따릅니다.
오늘을 보고 있던 상태로 날짜가 바뀌면 다음 날을 표시합니다. 다른 날짜를 골라 보고 있었다면 그 선택은 유지합니다.

달력은 진행 중인 할 일을 보여줍니다. 완료·제외된 일은 목록의 해당 분류에서 다시 열 수 있습니다.
날짜 없는 일과 확인이 필요한 항목은 임의로 달력에 배치하지 않고 아래의 목록 연결로 보여줍니다.
지난 마감일은 원래 날짜에 남기고, 오늘 챙길 일 안내에서도 다시 확인할 수 있습니다.

## 달력에서 직접 추가하기

1. 달력에서 원하는 날짜를 고른 뒤 **이 날짜에 일정 추가**를 누릅니다. 예정일은 선택한 날짜로 채워집니다.
   날짜를 **두 번 누르거나**, 화살표 키로 날짜를 옮긴 뒤 **Enter**를 누르면 그 날짜로 바로 입력 창이 열립니다
   (한 번 누르면 날짜만 고르고 그날의 일정과 메모를 보여줍니다).
2. 일정 이름을 적고 **추가**를 누릅니다. 마감일과 태그는 선택 사항입니다.

등록 즉시 달력과 할 일 목록에 표시되고, 등록 내용은 검색 가능한 메모에도 함께 저장됩니다.
‘직접 추가’ 표시로 구분하며, 완료·날짜 수정·다시 보기는 기존 할 일과 같습니다.
예정일 변경은 **수정·날짜**에서 할 수 있습니다. 메모를 재분석해도 직접 만든 할 일과 수정 내용은 유지됩니다.
등록 메모를 삭제하면 연결된 할 일도 삭제되며, 등록 메모를 보관하면 할 일에서 숨겨집니다.

## 태그로 일정 모아 보기

- 일정 입력 창과 일정 카드의 **태그 추가 / 편집**에서 **설정 → 내 태그**에 등록한 태그를 최대 20개까지 선택합니다. 선택한 태그를 다시 누르면 해제됩니다.
- 메모에서 추출한 일정은 메모의 태그를 기본으로 사용합니다. 일정에서 태그를 편집하면 메모 원문을 바꾸지 않고 따로 저장합니다.
- 상단 **태그** 필터나 카드의 색상 태그를 누르면 해당 태그의 일정만 표시합니다. 달력 건수와 목록 분류 건수에도 적용됩니다. **필터 해제**로 전체를 봅니다.
- 내 태그로 걸러 보고 있을 때 새 일정을 만들면 해당 태그가 미리 선택됩니다.
- 외부 일정에도 태그를 붙일 수 있습니다. 같은 일정 ID로 새로고침하면 붙인 태그를 유지합니다. 원본 서비스의 태그는 변경하지 않습니다.
- 받은 `.ics` 파일의 `CATEGORIES` 태그도 읽습니다. 지원되는 문자·길이 안의 태그만 가져옵니다.

## 다른 사람에게 일정 파일 공유하기

1. **일정 → 일정 공유**에서 기간을 정하고 **공유할 내 태그**를 고릅니다. 여러 개를 고르면 그중 하나라도 붙은 일정이 표시됩니다. 태그 없이 기간 전체를 보려면 **기간 내 전체 일정**을 선택합니다.
2. **공유할 일정 확인**을 눌러 제목·날짜·태그를 확인합니다. 개별 체크 또는 전체 선택/해제로 보낼 항목을 고릅니다.
3. **선택한 일정 파일 저장**으로 `.ics` 파일을 저장한 뒤 메신저나 메일로 전달합니다.
4. 상대는 이 앱의 **일정 → 외부 캘린더 → 일정 파일(.ics)**에서 가져옵니다. `.ics` 가져오기를 지원하는 다른 캘린더에서도 사용할 수 있습니다.

진행 중인 일정과 대기 중인 일정 중 날짜가 있는 항목만 공유합니다. 완료·제외·확인 필요 항목과 날짜 없는 일은 제외합니다.
예정일과 마감일이 다르면 별도 일정으로 표시하며, 같은 날짜·기간이면 하나로 합칩니다. 기간에 걸친 일정은 원래 전체 기간으로 공유합니다.
외부 일정은 **가져온 외부 일정도 포함**을 선택해야 공유합니다. 외부 일정의 장소·상세 내용은 별도로 선택하고 미리보기에서 확인합니다.
메모 원문·AI 근거·캘린더 연결 주소는 내보내지 않습니다. 미리보기와 파일의 태그 목록에는 설정의 **내 태그**에 등록된 이름만 담습니다.
미리보기 이후 선택한 일정이 바뀌면 다시 확인해야 저장할 수 있습니다. 미리보기는 2시간 동안 유효합니다.

공유에 서버나 계정 로그인이 필요하지 않습니다. 파일은 저장 시점의 사본이며 실시간 공동 편집이나 자동 동기화는 하지 않습니다.
변경 사항은 새 파일로 다시 보내 주세요. 이 앱에서 같은 캘린더 이름으로 다시 가져오면 기존 공유 일정을 갱신합니다.

## 네이버·구글 등 외부 캘린더 가져오기

달력의 **외부 캘린더**를 눌러 가져오기 창에서 파일이나 주소를 선택합니다. AI 키가 필요하지 않습니다.

| 서비스 | 가져오는 방법 |
|---|---|
| 네이버 캘린더 | PC 캘린더에서 캘린더명 옆 메뉴 → 가져오기/내보내기(백업) → 내보내기로 저장한 `.ics` 파일 선택. [네이버 공식 안내](https://help.naver.com/service/5620/contents/18401?lang=ko&osType=PC) |
| 구글 캘린더 | 설정 → 내 캘린더의 설정 → 캘린더 통합 → ‘iCal 형식의 비공개 주소’를 복사해 주소 연결에 입력. [구글 공식 안내](https://support.google.com/calendar/answer/37648?hl=ko) |
| 구글 파일 내보내기 | 내보낸 ZIP의 압축을 풀고 개별 `.ics` 파일 선택. [구글 내보내기 안내](https://support.google.com/calendar/answer/37111?hl=ko) |
| 기타 캘린더 | 해당 서비스에서 제공하는 `.ics` 파일 또는 HTTPS iCal 주소 사용. `webcal://` 주소는 HTTPS로 연결. |

캘린더 이름, 가져올 기간(최대 1년), 표시 시간대를 정하고 **미리보기 → 달력에 적용**을 누릅니다.
미리보기는 추가·변경·유지·삭제될 건수와 앞의 30개 일정을 보여 줍니다. 실제 저장은 적용할 때만 합니다.
조회한 기간의 전체 일정이 적용되며, 시간·장소·설명은 날짜별 목록에서 확인합니다.

- 주소로 연결한 캘린더는 **새로고침**을 누르면 변경 내용을 미리 볼 수 있습니다. 기간·시간대를 바꾼 뒤 다시 미리보기를 누르면 등록된 주소를 그대로 사용합니다.
- 파일 캘린더는 **새 파일로 갱신**을 눌러 새로 내보낸 파일을 고릅니다. 같은 캘린더 이름으로 가져오면 중복 없이 갱신합니다.
- 같은 캘린더를 갱신하면 저장된 외부 일정 전체를 선택한 기간의 새 내용으로 교체합니다. 원본에서 삭제되었거나 새 기간에서 빠진 일정도 삭제될 수 있으며, 미리보기에서 삭제 건수를 확인합니다.
- **연결 해제**는 이 앱의 연결 정보와 가져온 외부 일정을 삭제합니다. 원본 서비스의 일정과 직접 만든 할 일에는 영향을 주지 않습니다.
- 비공개 iCal 주소는 앱의 로컬 DB에 저장되며 화면·목록 API에는 다시 노출하지 않습니다. 미리보기는 2시간 동안 유효합니다. 네트워크 오류나 파일 오류가 나면 기존 일정을 유지합니다.

연동 범위는 **읽기 전용 가져오기와 수동 새로고침**입니다. 계정 OAuth 로그인, 양방향 수정, 자동 주기 동기화는 포함하지 않습니다.
외부 일정은 메모나 할 일로 자동 변환하지 않으며 AI 분석 대상으로 보내지 않습니다.
날짜·시간대·종일 일정의 종료일, 일/주/월/년 반복, 예외일, 개별 반복 일정 변경·취소를 반영합니다.
가져오기 범위는 1970~2100년, 파일 2MB, 최대 5,000개 일정입니다. 시간·분·초 단위 반복 및 VTODO/VJOURNAL은 지원하지 않습니다.
주소는 외부 HTTPS만 허용하며 로컬·내부 네트워크 주소는 차단합니다. 로그인 페이지 주소 대신 실제 iCal 주소가 필요합니다.

### 로그인 연동과의 차이

ICS는 서비스 간에 일정을 주고받는 공통 형식입니다. 현재 앱에는 파일 가져오기와 iCal 주소 연결이 구현되어 있으며, 로그인 연동은 별도의 구현이 필요합니다.

- **구글:** 공식 Calendar API와 OAuth 로그인으로 캘린더를 읽어올 수 있습니다. 앱에서 사용할 Google Cloud 프로젝트, Calendar API 활성화, 데스크톱 앱용 OAuth 클라이언트와 동의 화면 설정이 필요합니다. 지속적으로 사용하려면 로그인 후 캘린더를 선택하는 방식이 더 편리할 수 있습니다. [공식 Python 안내](https://developers.google.com/workspace/calendar/api/quickstart/python)
- **네이버:** 공개된 네이버 로그인 기반 캘린더 API는 일정 **추가**용으로, 가져오기를 위한 일정 목록 조회 API는 해당 명세에서 제공하지 않습니다. [공식 캘린더 API](https://developers.naver.com/docs/login/calendar-api/calendar-api.md)
- **네이버 CalDAV:** 별도로 계정 기반 캘린더 연결을 안내하고 있습니다. 2단계 인증 계정은 애플리케이션 비밀번호를 사용합니다. 공식 안내가 iOS·macOS 중심이므로 이 Windows 앱에 넣기 전 실제 계정과 클라이언트 호환성을 확인해야 합니다. [공식 CalDAV 안내](https://help.naver.com/service/5620/bookmark/2426?osType=COMMONOS)

## 선택적으로 AI로 정리하기

1. 상단 탭의 **설정**에서 사용할 AI 서비스와 API 키·모델을 저장합니다.
2. **일정** 화면에서 최근 7일·30일·90일 중 기간을 고르고 **할 일·날짜 제안받기**를 누릅니다.
3. AI가 제안한 새 할 일과 변경 전후 내용을 확인합니다. 각 제안에서 근거 문장과 원문을 열 수 있습니다.
4. 원하는 제안만 체크하고 **선택한 N건 적용**을 누릅니다. 완료·제외 제안은 기본으로 체크하지 않습니다.
5. 필요하면 **적용 취소**로 그 결과에서 적용한 변경 전체를 되돌립니다.

현재 설정에서 선택한 AI 서비스를 사용합니다. 선택한 서비스의 API 키가 없으면 버튼은 비활성화되고
AI 설정 안내가 표시됩니다. 기존 설정 방식에 따라 Ollama는 API 키 없이 선택한 로컬 모델로 실행할 수 있습니다.
메모 저장·앱 시작·할 일 화면 조회·재분석으로는 AI를 자동 호출하지 않습니다.

AI는 누락된 행동을 추가하거나 이름·마감·다시 볼 날짜·대기 상태를 정리할 수 있습니다.
선택한 기간의 다른 메모에 완료 기록이 있으면 기존 항목에 근거를 연결해 완료를 제안할 수 있습니다.
중복으로 판단한 기존 항목에는 제외를 제안할 수 있으며, 자동으로 삭제하지 않습니다.
직접 수정한 이름·상태·마감·다시 볼 날짜는 AI 제안보다 우선합니다.
AI 적용값과 직접 수정한 값을 구분해 저장하므로, 다음 AI 정리에서는 이전 AI 제안을 다시 보완할 수 있습니다.

분석 대상은 선택한 기간에 작성한 메모 중 최신 30건까지입니다. 보관한 메모와 AI로 생성해 저장한 메모는 제외합니다.
한 메모는 최대 3,000자, 원문 전체는 최대 22,000자까지 보내며, 결과에 분석한 메모 수·제외 건수·부분 분석 여부를 표시합니다.
선택한 기간 밖의 메모나 발췌되지 않은 부분까지 읽은 결과는 아닙니다.
설정한 AI 서비스에는 이 메모 내용과 해당 메모의 기존 할 일 정보가 전달됩니다.

결과를 만들 때는 할 일을 변경하지 않습니다. 적용 단계에서도 실제 원문에 없는 인용·출처와
기록에서 확인할 수 없는 날짜는 걸러냅니다. 미리보기 이후 근거 메모나 할 일이 바뀌면
적용을 막고 다시 정리하도록 안내합니다. 네트워크 오류나 형식 오류가 나도 기존 목록과 이전 미리보기는 유지합니다.

AI로 새로 추가한 할 일은 규칙 재분석 후에도 유지됩니다. 근거가 바뀌거나 사라지면 원문 확인 안내를 표시합니다.
적용 취소는 이후 해당 항목을 다시 수정하지 않았을 때 가능합니다. 다른 수정 내용을 덮어쓰는 일괄 취소는 막습니다.
미리보기는 다른 메뉴로 이동해도 유지되지만 앱을 종료하거나 페이지를 새로고침하면 화면에서는 다시 정리해야 합니다.

## 현재 범위

기본 추출은 로컬 규칙 기반이며, AI 정리는 버튼으로 요청했을 때만 보강합니다.
여러 메모를 같은 업무로 자동 병합하거나 AI 판단만으로 완료 처리하지 않습니다.
직접 만든 할 일의 반복 생성과 시간 단위 알림은 포함하지 않습니다. 외부 캘린더의 반복 일정은 지정한 기간 안에서 가져옵니다.
요청과 회신 예정일은 같은 줄에서 바로 이어지는 문장인 경우 함께 읽습니다.
새로 추가한 규칙을 실제 메모 사례로 보완할 수 있도록 원문 근거를 유지합니다.
